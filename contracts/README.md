# EnFractal contracts

Run 0 output, 6 October 2026. These schemas are the agreements between the four tracks (Look, Capture, Play, AI companion). Parallel lanes build against them instead of against each other's code. **The integrator owns this directory.** A lane that needs a change proposes it; the integrator applies it here together with every affected example, consumer and test in one commit.

| Contract | File | Written by | Read by |
|---|---|---|---|
| Shared definitions | `common.schema.json` | integrator | every contract |
| Room manifest (`room.json`) | `room-manifest.schema.json` | Capture export (C6), `tools/rooms/` for hand-built rooms | Play room loader (P6), Look (light hints, roles), AI (observations) |
| Asset metadata (`asset.json`) | `asset.schema.json` | Capture assets (C5), Look restyle (L6, the `styles` block only) | Play loader and sandbox verbs (P3, P6), Look materials (L3), AI |
| Style preset | `style-preset.schema.json` | Look (L1, L3, L5, L6) | Look runtime, Capture restyle stage, room and state pins |
| Command, query, result | `game-command.schema.json` | manual controls (P3, P5), AI adapter (A1), tests | the kernel (P1) and everything that records receipts |
| Room state | `room-state.schema.json` | saves (P4) | room rebuild (P6), undo, reconcile |

Examples live in `examples/` and are generated by `examples/build_examples.py`. The placeholder room `game/rooms/test_room/` is generated by `tools/rooms/build_test_room.py` and the seed preset is `game/styles/storybook_painterly.json`. The game loads them through `game/scripts/native/Room/` and `game/scripts/native/Look/`.

## Validate

```sh
uv venv .venv && uv pip install -r contracts/requirements.txt   # or python -m venv + pip
python contracts/validate.py game/rooms/test_room game/styles/storybook_painterly.json
python contracts/validate.py --state path/to/state.json --room path/to/room_dir
python contracts/validate.py --pin game/styles/storybook_painterly.json
python -m unittest discover -s contracts/tests -v
```

`validate.py` checks the schema and the rules a schema cannot express: unique ids, resolvable references, every referenced file listed with a matching hash and size, planar shell polygons wound toward the room interior, unit quaternions, spawns and objects inside the bounds, state pins and receipt consistency. The C# loader (`game/scripts/native/Room/RoomData.cs`) enforces the integrity subset again at load time and fails closed.

## Conventions every contract shares

- **Units and axes.** Metres, kilograms, seconds, degrees. Godot axes: +Y up, -Z forward, right-handed, 1 unit = 1 metre. Asset pivots are the bottom centre of the asset's bounds.
- **Pins hash bytes, not meaning.** A room's identity is the SHA-256 of its `room.json` bytes. A preset's identity is the SHA-256 of its file bytes. `room.json` lists every file it references with hash and size, and each `asset.json` lists its own files, so one room pin covers everything below it. Pinned files are UTF-8 without a byte-order mark and use LF line endings; `.gitattributes` enforces this on every checkout. Never hand-edit a generated room: rerun its builder.
- **Strict JSON.** Duplicate keys, `NaN`, `Infinity` and numbers that overflow are rejected. Unknown fields are rejected (`additionalProperties: false`) except inside `extensions`, whose keys start with `x_<lane>_` and which consumers must ignore. The integrator promotes or deletes extension keys; they are for experiments, not for skipping a contract change.
- **Identifiers.** Lowercase tokens for rooms, assets, presets, spawns, parts and jobs. Entity ids are namespaced: `shell:`, `obj:`, `creation:`, `avatar:`, `effect:` and legacy `edit:`. Principals are `player:`, `companion:`, `guest:`, `guest_companion:` or `system:` followed by a token.
- **Principals never travel in requests.** The trusted adapter assigns the principal; a request that carries one is invalid. Results echo it for audit. This is the rule that keeps a persuaded AI, or later a guest's AI, from claiming the player's authority.
- **Approvals are minted by the game UI, never by a model.** A destructive command can come back with `approval_needed`; only the player's click in the game issues the `approval_id` that the retried command carries, bound to that exact command and an expiry.
- **World text is untrusted.** Names, labels and signs reach the AI only inside `observe` results as `texts` entries with `untrusted: true`, a constant the schema enforces.
- **Idempotency.** Same principal + same `action_id` + same content returns the original receipt with `replayed: true`. Same `action_id` with different content is refused with `action_id_conflict`. Previews record no receipt. After an uncertain result, query `receipt.lookup` before retrying.

## Versioning and change protocol

Each document carries `schema` and an integer `version`. Within a version, the integrator may add optional fields. A change that would make an existing valid document invalid, or change the meaning of a field, bumps `version` and comes with a migration note in this file and a converter where saved data exists. A lane requesting a change writes the proposed diff and its reason in its run report; it does not edit `contracts/` itself.

## How today's kernel maps onto the command contract

`game/scripts/creation_authority.gd` implements a single-plot subset of this contract. The Play track's P1 packet migrates it. Until then, adapters translate as follows.

| Contract | Current authority |
|---|---|
| `creation.place` with `placement.position_m` | `submit` op `place` with `source`, `x_m`, `z_m`, `yaw_deg` (height from terrain sampler) |
| `creation.revise` | op `revise` with `instance_id` |
| `entity.remove` on a `creation:` id | op `remove` |
| `creation.activate` | op `activate` (transient receipt) |
| `expected_revision` (one counter) | `expected_revision` and `expected_permission_revision`; the authority already increments the room revision on permission changes, so one counter is sufficient |
| principal `player:local` / `companion:local` | `local_player` / (none yet) |

| Contract error code | Current authority codes |
|---|---|
| `request_invalid`, `field_unknown`, `action_id_invalid`, `action_id_conflict` | same names, plus `operation_invalid` and `request_invalid` |
| `revision_conflict` | `revision_conflict`, `permission_revision_conflict` |
| `not_ready` | `save_not_ready`, `configuration_invalid` |
| `permission_denied` | `build_denied`, `ownership_denied`, `role_denied`, `activation_denied`, `consent_denied` |
| `target_not_found` | `instance_not_found` |
| `target_protected` | `protected_zone` |
| `out_of_bounds` | `plot_bounds`, `placement_invalid` (non-finite placement is `invalid_args`) |
| `occupied` | `avatar_occupied`, `occupancy_unavailable` |
| `budget_exceeded` | `runtime_budget`, `json_budget`, `part_budget`, capacity codes |
| `receipt_limit`, `state_limit` | `receipt_limit`, `activation_receipt_limit`, `state_limit` |
| `persistence_uncertain` | a persistence sink that did not acknowledge commit |

The creation manifest (`enfractal.creation`) is not duplicated here: the command contract checks only its envelope and `creation_compiler.gd` remains its authority.

## Known open points for later runs

- Canonical JSON for command fingerprints and creation `source_sha256` must be byte-identical across GDScript, C# and Python. Run 1's P1 packet owns a shared golden fixture before any cross-language hash is compared.
- `observe` field-of-view rules, `capabilities.list` payloads and `jobs.status` payloads are A1 deliverables; their result `data` is free-form until then.
- Health, damage and hit primitives for the dragon scenario arrive with A4 as a version 2 command vocabulary.
- Shared room libraries (an asset referenced by many rooms) and room-to-room portals need path forms the current `rel_path` rule forbids; they are deliberately out of version 1.
