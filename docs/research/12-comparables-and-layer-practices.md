The useful comparison is not “which game looks most like EnFractal?” No existing reference here combines a geographic shared Earth, painterly semantic construction, permissioned inventions, invited physics variants, and a player AI assistant. Each row instead names a proven mechanism at one layer, its boundary, and a small test suitable for one founder with coding agents and an initial **under-$100/month hosting-plus-AI ceiling**.

## Strategic lessons for the MVP

1. **Prove a place and an edit, then add breadth.** 3DEP/STAC and Cesium show how to prepare and display geography; Tiny Glade shows adaptive construction; neither proves that one lasting invention is enjoyable in a shared place. The acceptance scene should combine a recognizable Barton Creek route, one revised semantic join and two people before another region or a larger asset library.
2. **Keep visual derivatives replaceable and authority durable.** Godot/Cesium/Roblox streaming mechanisms are valuable for presentation, while PostgreSQL-style receipts and a single authority protect ownership and persistence. Low settings may remove leaves, not hazards, colliders, rights or changed-world meaning.
3. **Make composition more important than unlimited primitives.** Roblox constraints and Tiny Glade's responsive joins suggest that a small grammar can feel broad if parts interact usefully. Human review can expand that grammar after measured examples; exposing arbitrary player code would make every subsequent safety and cost gate harder.
4. **A small host is a product constraint, not an infrastructure embarrassment.** A queued sandbox slot, offline map packages, optional paid inference and honest concurrency cap fit the founder's budget better than a global always-on service. Add cells and services only after real concurrency and return-use data justify them.

## Rights and data-use boundary

- [USGS 3DEP](https://www.usgs.gov/3d-elevation-program/about-3dep-products-services) states its products are free/public domain, but confirm the exact downloaded asset's metadata, reference system and acquisition before packaging it. [PROJ's vertical-grid documentation](https://proj.org/en/stable/operations/transformations/vgridshift.html) shows why a horizontal CRS alone does not establish comparable heights. Barton Creek's current source vertical reference is still unresolved in the phase 0 contract.
- [OSM Foundation's ODbL guidance](https://osmfoundation.org/wiki/Licence_and_Legal_FAQ) applies to substantial OSM-derived data even when a game is commercial. Preserve attribution, source version and the extract/derivative-database analysis; isolate non-OSM and player-authored layers. The MIT license on a downloader or QGIS plugin does **not** license its source imagery.
- [Maxar's Open Data protocol](https://maxar-marketing.s3.amazonaws.com/files/downloads/119757_opendataprotocol_2020_04.pdf) assigns CC BY-NC 4.0 to the cited event imagery, so do not bundle it into a potentially paid game on the strength of the [MIT-licensed QGIS plugin](https://github.com/opengeos/qgis-maxar-plugin). Verify current rights and any scene-specific terms before even using imagery as a distributable derivative. An online photo is not free game texture or photogrammetry input merely because it is viewable.
- Blender's [license explanation](https://docs.blender.org/manual/en/4.2/getting_started/about/license.html) distinguishes the GPL program from artwork produced with it. Still record the license of **each** input photograph, texture, model, sound and procedural asset; preserve a clean-room path for a later paid release and outwardly distributable map package.
- These comparisons authorize learning from published behavior and documentation, not copying another game's art or code. If a library is incorporated, review its actual license and notices separately: [Godot is MIT-licensed](https://godotengine.org/license/), [CesiumJS is Apache-2.0](https://github.com/CesiumGS/cesium/blob/main/LICENSE.md), and [Luanti's repository identifies LGPL-2.1](https://github.com/luanti-org/luanti). No source transfer is proposed by this document.

## Open verification gaps, in recommended order

1. **Map truth:** the builder now labels inferred OSM building heights correctly for future map IDs, with a Barton mall regression fixture. The shipped `barton_creek_v0` stays pinned and reproducible with its documented historical estimate-field error; a corrected v1 candidate is not yet an adopted playable package. Confirm the real source resolution and DEM vertical reference, choose an explicit v0-to-v1 migration or display annotation, and add a versioned frame/surface-algorithm pin before cross-region placement.
2. **Engine and device:** native Windows and Linux headless exports from one pinned Godot/source snapshot now pass basic startup; a bounded ENet+DTLS loopback rejects incorrect server identities and plaintext traffic. Neither establishes a production authenticated session, remote network behavior, server stress, C# maintainability or a real low-spec integrated-GPU device. The development RTX moving-route probe exposes hitches. Feasibility evidence; transport experiment.
3. **Edit ownership:** the local path/platform relationship now enters the workshop preview, colliders and saved semantic source parts, and it regenerates on endpoint revision. It still lacks a synchronized authoritative visual/collision revision handoff and the painterly art reference is separate from the edited scene. Workshop evidence.
4. **Shared consequences:** write executable golden fixtures for canonical command bytes, idempotent receipt lookup order, stale revisions, ACL changes and a failed portal transfer. The phase 0 document is a proposal until cross-layer reviewers agree and the dependent packets implement it.
5. **Player and spending evidence:** founder walk-through for AI's visible-companion priority, first-time-player observations, actual service/AI charges, backup restoration and explicit invite/privacy/moderation rules remain open. No comparable project's published defaults substitute for those EnFractal measurements.
