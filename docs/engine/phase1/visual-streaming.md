# Phase 1 visual terrain streaming spike

The Barton Creek viewer now prepares one visual LOD tile at a time on a Godot worker. Its CPU job produces only packed vertex, normal, color, UV and index arrays. The main thread creates the `ArrayMesh` and replaces the visible `MeshInstance3D.mesh` after the job completes. The prior mesh stays visible until then. This isolates the expensive 2 m tile calculation without making the active scene tree or GPU upload a worker operation, in line with Godot's [thread-safe API guidance](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html).

The scheduler holds at most one in-flight job and 64 pending tile IDs. It rechecks the camera's desired LOD when a job finishes: a large jump makes that result stale, so it is discarded and the old mesh remains. An in-flight calculation is not preempted; it finishes before the next tile starts. Every `WorkerThreadPool` task is joined, including during viewer shutdown, as required by [Godot's WorkerThreadPool contract](https://docs.godotengine.org/en/stable/classes/class_workerthreadpool.html). The map package is read-only while a job runs. No scene nodes, meshes or textures are created or changed in the worker.

All three LODs keep the same source-derived 2 m tile-edge heights. The existing seam test checks 2/8/32 m combinations and upward triangle winding. Fine, medium and coarse tiles contain 131,072, 9,464 and 1,592 triangles respectively. Collision remains on its separate, fixed-resolution path; a visual LOD swap cannot remove an active collider.

## Diagnostic measurements

Five fresh headless Godot 4.7.2 runs on the development laptop used one 512 m Barton Creek tile, forced one stale 2 m request, then built and committed one valid 2 m request. Worker dispatch took **0.04–0.05 ms**, the CPU build took **93.19–95.19 ms** off the main thread, and the main-thread mesh commit took **5.11–5.64 ms**. The previous synchronous fine-tile build took about **104–106 ms** on this machine in the same headless geometry test. These are local diagnostics, not warm gameplay frame percentiles or a low-device pass. The hidden-window renderer and target 8 GiB integrated-GPU machine still need route-based profiling.

A separate hidden-window greenbelt capture at 1280×720 on this laptop's RTX 2070 Super exited successfully with an empty LOD queue. Its last 8 m build took 29.96 ms off-thread and commit took 1.30 ms; 42 settled frames had a reported 6.94 ms median and p95. The camera was stationary, and hidden-window timing is not representative of a walking or high-speed travel route.

A fine tile's packed vertex/index arrays account for roughly **4.52 MiB**; the worker also uses a temporary height cache of roughly **0.26 MiB**. Those figures exclude Godot object overhead, upload copies, resident meshes, other map features and GPU allocation. One job bounds temporary CPU output, but the prototype still creates all 64 coarse tiles synchronously at startup and retains tile meshes rather than evicting them. Package loading and mapped-feature construction also remain synchronous.

Run the focused checks with `godot --headless --path game --script res://tests/terrain_seam_smoke.gd` and `godot --headless --path game --script res://tests/visual_streaming_smoke.gd`. The streaming test confirms that dispatch leaves the coarse tile visible, a stale result is discarded, a valid result is later committed, and the 2 m triangle count is intact. The existing map, movement, creation, world-state, world-physics and workshop integration headless tests also passed in this phase.

The next E06 step is a real residency and travel benchmark: move through several tiles and a portal-scale jump while measuring p95/p99 frame time, upload stalls, queue age, resident CPU/GPU memory and collision continuity on the specified low device. An exported release build needs the same test. If upload or startup still spikes, budget main-thread commits and phase coarse startup; if travel leaves unneeded fine meshes resident, add bounded eviction and reload. This spike proves one safe worker path, not full geographic streaming.
