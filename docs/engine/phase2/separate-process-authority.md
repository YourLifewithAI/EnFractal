# Separate-process shared-authority fixture

**Status: bounded phase 2 evidence, 2 October 2026. E09 and E10 remain open.** This extends the [single-process adversarial prototype](shared-authority-prototype.md) without changing the playable game or its map package.

The [runner](../../../tests/run_authority_process_smoke.ps1) starts three headless Godot 4.7.2 processes on Windows: one authority, Alice and Bob. A fourth *connection* inside Bob's process tests ticket replay, but there are only three processes. The runner matches each self-reported process ID to the actual launched process, checks a fresh run ID, exact expected case names and exit codes, and pins the Godot executable and five source files by SHA-256 before and after the run. The authority binds ENet+DTLS to `127.0.0.1` on an OS-assigned port. Clients trust only its per-run public certificate and validate the expected test hostname before using their one-use ticket. The authority keeps the private key in memory. Its public certificate, bearer tickets and two synthetic session values live in a temporary local directory that the runner deletes. These are fixture credentials, not real player accounts. The retained evidence report contains none of their values.

The authority's [model](../../../tests/shared_authority/authority_model.gd) validates a ticket, binds an application session to the actual encrypted connection and accepts only typed movement intentions. Once both clients have submitted a valid intention, the fixture authority applies **one** server-owned 30 Hz-sized simulation step and broadcasts tick 1. Both separate client processes independently verify the received tick, rules revision and both avatar positions. The runner compares their reported snapshots with the authority's result within 0.000001 m. Alice's expected x position is `(3 + 1) / 30` m from movement plus server wind while gliding; Bob's is `-3 / 30` m. Each client enforces an exact snapshot field allowlist and sees only its own synthetic private marker, with the other marker absent.

The 31 passing checks include preadmission denial without a world snapshot, ticket replay from Bob's extra connection, a copied session value rejected on Bob's authenticated connection, forged position/owner/wind fields, duplicate sequence, wrong world and stale epoch. The rejected replay connection stays open through the tick-1 broadcast: the server confirms one unadmitted peer was connected while it sent snapshots only to the two admitted peers, and Bob confirms his rejected connection received no snapshot afterward. The authority checks that every rejected model packet leaves its state fingerprint unchanged at the same tick. A final test-only completion message is accepted only from a session bound to that connection; it does not advance simulation.

Run locally:

```powershell
pwsh -NoProfile -File D:\Enfractal\tests\run_authority_process_smoke.ps1
```

The runner has a 35-second overall limit and requires a clean report from each process. The retained [Windows loopback result](evidence/authority-multiprocess-loopback-windows-2026-10-02.json) completed 31/31 checks in **4,518 ms**; another fresh run passed 31/31. Its authority report records three connected peers at tick 1 and two snapshot recipients. Before retaining a report, the runner checks that neither ticket nor either synthetic session value appears in its serialized text. Godot's [ENetConnection DTLS API](https://docs.godotengine.org/en/stable/classes/class_enetconnection.html) and [X509Certificate API](https://docs.godotengine.org/en/stable/classes/class_x509certificate.html) underlie the local test. The certificate is written as a temporary public `.crt` file; saving the PEM to a Godot string emitted a NUL conversion warning on this engine build, so this fixture does not use that path.

This is **not** a Linux-host or exported-client result. Ubuntu under WSL2 and the official Linux Godot 4.7.2 editor are available locally, but this packet does not start the authority there or establish Windows-to-WSL routing. The Linux release export template rejects `--path` overrides, so a cross-host follow-up needs the editor binary or a packaged Linux server plus a dual-path temporary certificate/config handoff. The current fixed step is event-triggered after two accepted intentions, rather than a measured wall-clock 30 Hz server loop. There is no packet loss, latency, prediction, terrain collision, world edit, persistence, authentication service, durable receipt, hosted public listener or capacity test. Reconnect fencing and malformed/oversized packets are covered in the prior single-process fixture, not repeated in this three-process test. Do not treat either fixture as E09/E10 completion.
