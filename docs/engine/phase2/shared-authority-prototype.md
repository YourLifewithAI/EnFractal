# Transient shared-authority loopback prototype

**Status: bounded E09/E10 engineering evidence, 1 October 2026. E09 and E10 remain open.** This follows the [adversarial fixture design](shared-authority-test-design.md), [15 data-only scenarios](../../../tests/fixtures/phase2_authority_vectors.json), [contract v0.1](../phase0/contract-v0.1.md) and [transport path proof](transport-feasibility.md). It changes no playable game, map package or persistent world state.

The follow-up [separate-process fixture](separate-process-authority.md) now runs Alice, Bob and the authority in distinct Windows Godot processes. The prototype below remains useful for its broader packet and reconnect cases.

The [isolated Godot project](../../../tests/shared_authority/project.godot) creates one transient authority and five independent ENet client connections **inside one Windows Godot process**. Alice and Bob are the two gameplay clients; the other connections test reused/missing tickets and reconnect. Every endpoint binds to `127.0.0.1` on an OS-assigned port. The server uses an ephemeral in-memory key and certificate; clients configure `TLSOptions.client()` with that trusted certificate and the expected hostname before connecting. The separate [transport probe](transport-feasibility.md) has already shown a wrong hostname, unrelated/expired certificate and plaintext client cannot deliver application data in bounded local tests. This prototype itself exercises the successful certificate-validated connection, not a new wrong-hostname case. No public listener, external account, real credential or saved private key is involved.

The [authority model](../../../tests/shared_authority/authority_model.gd) generates 256-bit random one-use admission tickets. It stores only their SHA-256 digests, with avatar/world/frame/epoch and a 30-second expiry, and binds a redeemed ticket to the encrypted connection and a fresh random application session. The fixture does not prove ticket issuance through an authenticated HTTPS control service, concurrent redemption, expiry rejection, cross-world reservation or account identity. Reconnection replaces the active avatar session; old connection packets and snapshots lose authority. Session and ticket values are absent from the saved test report.

Only bounded typed movement intentions enter the model. The authoritative 30 Hz fixture tick owns a flat cell, speed limit, simple glide/wind displacement and positions. This is a deliberately small kinematic seam, **not** the playable terrain/CharacterBody physics, a realistic glide model or a final tick rate. The server rejects packets containing claimed position, actor/owner, wind/rules or client elapsed time. It rejects copied sessions, stale world/epoch, duplicate sequences, excessive axes, nonnumeric axes, malformed identity/epoch types, unknown operations and packets above 1,000 bytes before decoding. It sends same-tick shared positions to admitted Alice and Bob and filters a synthetic private marker to its rightful recipient. No client supplied value can directly set authoritative position or rules.

The [Windows runner](../../../tests/run_authority_smoke.ps1) launches hidden headless Godot, creates a unique run ID, enforces a 30-second total limit, requires exactly the expected case names and a fresh passing report, rejects unexpected stderr/engine diagnostics, and exits nonzero on failure. Run:

```powershell
& 'D:\Enfractal\tests\run_authority_smoke.ps1'
```

Set `ENFRACTAL_GODOT` if Godot 4.7.2 is in another location. The observed report is [authority-loopback-windows-2026-10-01.json](evidence/authority-loopback-windows-2026-10-01.json): Godot **4.7.2-stable (official)**, Windows, loopback-only, 39/39 checks passed. The runner passed twice after the final probe changes, including a retained report run; its output and report contain no ticket, session value or private key. The result is functional evidence, not performance, capacity or security certification.

An independent review found that queued tick-0 snapshots could have made a naive two-client comparison pass after tick 1. The corrected check requires both clients' **received tick-1** snapshots to carry the expected authority epoch and rules revision and match the server-computed positions within 0.000001 m. A negative control deliberately withholds Bob's tick-1 packet while confirming a tick-0 packet is queued; the reader must ignore the stale packet and report no tick-1 observation. The reconnect test also now queues an old-session intent before replacement, verifies that tick 2 excludes it, observes that the old connection gets no tick-2 wire snapshot, and sees the replacement connection's own movement in its tick-3 wire snapshot. These are stronger observations than a direct model-state-only check.

The 39 checks are narrower than full conformance with the 15 design scenarios. The wrong-hostname case relies on the separate transport probe; `non_finite_move_axis` is represented here by a nonnumeric `"NaN"` field rather than a raw non-finite binary float; `oversized_packet` and `unknown_operation` have direct negative tests; admission expiry, concurrent redemption, flood/rate limits and privacy beyond one synthetic marker are not exercised. State-unchanged checks use an in-memory fingerprint at the same tick, not a canonical cross-language hash. The fixture has no simulated latency, loss or reorder; it cannot establish E10 interpolation, prediction or two-remote-client agreement. All endpoints share one process, so it also lacks separate-process/export and Windows-to-Linux host evidence.

Transient movement sequence rejection is **not** durable edit idempotency. A committed edit with an `action_id` must later return its original receipt on an identical retry under the phase 0/E15 rule; this prototype has no durable commands, database, receipts or crash recovery. It also has no actual account authentication, player permissions, parcel ACL, authoritative Barton collision, collider/visual revision activation, portal transfer, host restart/reconnect, production certificate operation, privacy review or bounded load. Those remain required before public hosting or a claim that E09/E10 passed.
