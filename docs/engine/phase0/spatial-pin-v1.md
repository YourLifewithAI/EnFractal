## Exact encoding

This is a narrowly scoped ASCII record format, not canonical JSON. Every descriptor field value is a string, including `grid_side_samples`. The byte stream is the ASCII header `enfractal-spatial-pin-v1` followed by LF (`0x0A`), then exactly one `key=value` record per field in the fixed lexicographic ASCII order listed in both implementations, each ending in LF. There is no BOM, whitespace, CRLF, trailing record, Unicode normalization, escaped value or optional field. The SHA-256 covers **all** bytes, including the domain header and final LF. Maximum encoded length is 8,192 bytes.

ASCII tokens permit letters, digits, `_`, `:`, `.`, `+`, `/` and `-`, start with a letter and are at most 128 characters. Payload hashes are exactly 64 lowercase hexadecimal characters. Decimals are normalized signed ASCII decimal strings without exponent, leading zero, trailing fractional zero or negative zero; they are bounded to absolute magnitude 1,000,000,000. Geographic latitude and longitude additionally stay within ±90 and ±180. Grid count is a decimal *string* from 2 through 65,536. `sample_spacing_m`, `side_m` and `tile_side_m` have at most millimetre precision and at most 1,000,000 m magnitude; the grid span and tile divisibility must match exactly. These deliberately tight limits can be revised only under a new profile/version, not silently relaxed by one language.

The descriptor names immutable map/frame identity and payload SHA-256s; EPSG:4326 geographic anchor; EPSG horizontal CRS; full-precision projected center; declared projection implementation/version and local axis meanings; grid, tile and height decoder; vertical datum/scope/transform; and the physical surface algorithm and outside-query rule. Barton uses UTM grid offsets, not true ENU. Its exact source vertical datum is unproven, so `vertical_datum_id=unknown`, `vertical_scope=local_only` and `vertical_transform_id=none` are compulsory. The `source_declared` scope in one **hypothetical** altered-datum vector only demonstrates hash sensitivity and is not a claim that Barton has a known datum or is globally interoperable. The alternate cell diagonal is also a hypothetical vector; it must never reinterpret the shipped collider silently.

The cross-language vectors cover Barton, hypothetical negative-elevation metadata, a synthetic second frame, hypothetical datum and collision-diagonal changes, and numeric boundaries. **Only the Barton vector validates a real package and its source terrain.** The negative-elevation vector reuses Barton payload hashes with hypothetical decoder fields; the second-frame vector hashes ASCII placeholder payloads, not a valid 17×17 height grid or playable package. Those vectors test exact byte encoding and hash sensitivity, not regional map decoding. The separate [Wellington map fixture](../phase1/map-contract.md) tests signed-height decoding. Python tests also reject duplicate JSON keys at a JSON ingestion boundary; both record decoders reject duplicate/reordered records. Godot's `encode(Dictionary)` is **typed input only**: `JSON.parse_string` discards duplicate-key evidence, so untrusted raw JSON must not be parsed directly into that encoder. Untrusted input must arrive as this checked record encoding and pass `decode`, or use a strict JSON parser before converting to a typed descriptor. The Godot probe's case JSON is a checked-in test fixture, not a network ingestion path.

Run `./tests/run_spatial_pin_v1_probe.ps1` to compare fresh Godot 4.7.2 bytes and hashes against the checked-in Python goldens. Run `./.venv/Scripts/python.exe -m pytest -q tests/test_spatial_pin_v1.py` for source-bound and malformed-input cases. The runner writes a temporary Godot result and never updates the golden file. A deliberate goldens change requires review of all decoded records and payloads.

## Migration proposal, not an implemented migration

1. Load and verify a schema-v2 local save against the **unchanged** v0 Barton package, using its existing Godot spatial hash and both payload hashes; retain the original save and action receipts.
2. Construct the v1 descriptor from the verified source package and fixed transform implementation. Check the complete projected origin, sampled corner/edge placement and `a-c-b` / `b-c-d` collision fixtures. Preserve `unknown/local_only` for Barton elevation unless independent evidence establishes a vertical reference.
3. Only after review, write a new schema and frame ID with both legacy and new pin references and an explicit migration receipt. Never recompute the old save's pin with Python, rewrite placements against the rounded manifest origin, treat local Y as geodetic height, or silently accept a changed surface algorithm.

Full E02 remains open: confirm the geographic transform and its installation/grid dependencies on target machines; resolve the source elevation datum before global placement; obtain map/physics/persistence/network/MCP agreement on frame, rule, command and error vectors; define the production schema and migration receipt; and prove loaded placement/collision equivalence before switching runtime state. This fixture supplies exact bytes and a validation pattern for those reviews, not hosted authority or a production protocol.
